# 控制极夜能源负荷与保障级别基础服务

本项目提供极地科考站服务端应用共用的基础能力，用于登记科考机构、站点、操作者和结构化业务资料，并提供角色权限、请求幂等、SQLite 事务与哈希串联审计。具体的物流、样品、能源、医疗和许可业务可在这些边界上扩展自己的状态、规则和接口。

在此基础之上，项目内置了**站内能源承诺与负荷处置系统**（`polar_station_energy`）：极夜大风导致风机停运时，值班工程师依靠有限的柴油与储能，决定哪些实验、生活保障和加热回路继续供电，并核验每一次限电决定不会造成冻损、燃料与能量账目能够闭合。

## 目录

- src/polar_station_foundation/：领域模型、SQLite 存储、权限服务、审计链、HTTP 路由和离线验收；
- src/polar_station_energy/：能源排程引擎、承诺方案与负荷处置服务、HTTP 路由和离线验收；
- tests/：基础规则、事务边界、接口路由、排程引擎、能源服务和端到端验收测试。

## 能源承诺与负荷处置

- **可控制的时间基准**：时间切分为 30 分钟时段，时钟可替换（`ManualClock`），发电、储能、燃料批次与分时需求在同一时段基准上连成预测；
- **回路规则**：配电回路带保障等级（医疗/通信/防冻必须供电）、依赖闭包、成组投切（绝不部分供电）、最低运行时长、启动代价与分时需求，实验回路只在获批窗口内供电；
- **燃料配给**：燃料批次带可用时段，补给迟到可登记顺延；排程按“累计可用燃料 − 累计保障需求”的后缀最小值为一般负荷配给，下一批燃料到达前不会透支医疗、通信与防冻的储备；
- **承诺方案**：草稿 → 两名不同操作者确认封存 → 被更新方案取代；同一时刻全站只有一个封存方案，多个确认请求也只封存一个；
- **人工覆盖**：必须双人确认且在期限内才生效，保障回路禁止覆盖切除，覆盖不能突破设备故障与获批窗口；
- **幂等结算**：遥测按时段入账，相同遥测重放不会重复结算能量，结算按时段单调推进，燃料按批次先进先出支取；
- **增量重算**：实际功率变化、设备故障或补给迟到后，只重新计算未来时段，已执行指令保持原样；
- **限电周期**：缺口出现即开启，重算只追加动作，恢复供电后由无切除的封存方案关闭；服务重启后未结束的限电周期继续推进；
- **可解释与对账**：每个回路每个时段都记录保留或切除的依据（`reason_code` + 中文说明），`reconcile` 核验燃料收入 = 消耗 + 剩余、供给 = 需求 ± 储能。

## 环境

- Linux
- Python 3.11 或更高版本
- 运行时仅使用 Python 标准库和 SQLite

## 测试

    PYTHONPATH=src python3 -m unittest discover -s tests -v

## 构建检查

    python3 -m compileall -q src tests

## 离线验收

    PYTHONPATH=src python3 -m polar_station_foundation.acceptance
    PYTHONPATH=src python3 -m polar_station_energy.acceptance

验收命令会在临时 SQLite 数据库中完成各自业务的端到端流程：基础服务核对登记链、幂等回执与审计链；能源系统执行“限电 → 结算 → 补给迟到 → 故障 → 人工覆盖 → 恢复 → 账目闭合 → 重启续推”的完整场景。成功时输出一行 status 为 ok 的 JSON 并以退出码 0 结束。

## HTTP 服务

    PYTHONPATH=src python3 -m polar_station_foundation.api --database polar_station.sqlite3 --host 127.0.0.1 --port 8080
    PYTHONPATH=src python3 -m polar_station_energy.api --database polar_energy.sqlite3 --host 127.0.0.1 --port 8081

健康检查使用 GET /health。写入接口通过 X-Actor-Id 标识操作者，服务重启后 SQLite 中的业务状态和审计历史继续保留。能源接口挂在 /energy/ 前缀下，包括资产与回路登记、预测、方案与确认、人工覆盖、遥测、限电状态、总览和对账；其余路径由基础服务处理。
